# Contributing to MotorcycleRAG

Thank you for contributing. Start with the [system onboarding guide](6-Docs/system/onboarding.md), [documentation standard](6-Docs/documentation-standard.md), and [component catalog](6-Docs/catalog.md).

## Before opening a pull request

1. Choose the owning component and read its scoped instructions and documentation.
2. Keep changes within the Clean Architecture boundaries and follow the repository working agreement.
3. Add or update focused tests for behavior changes.
4. Update the affected README, canonical documentation, and catalog entry when a documented interface, configuration, workflow, architecture, or component status changes.
5. Do not include credentials, tokens, customer data, or copied production configuration.

## Pull requests

Explain the problem, the component boundary, validation performed, documentation impact, and any operational or security considerations. Use the provided pull-request template and respond to review feedback constructively.

## Reporting defects

Use the issue forms for reproducible bugs and focused feature proposals. Do not report security vulnerabilities in public issues; follow [SECURITY.md](SECURITY.md).
