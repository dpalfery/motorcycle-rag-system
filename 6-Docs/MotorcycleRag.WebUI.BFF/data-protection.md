## Problem Statement

The BFF (Backend-for-Frontend) service authenticates users with Microsoft Entra ID via OpenID Connect and stores session state in encrypted HTTP cookies. ASP.NET Core Data Protection generates the symmetric encryption keys used to protect these cookies.

**Without persistent key storage**, each container instance generates ephemeral keys that exist only in memory. This causes two failure modes:

| Failure Mode | Symptom | Error |
| --- | --- | --- |
| Container restart | All active sessions are invalidated | `IDX21329: Unable to validate token` |
| Scale-out (multiple replicas) | Sessions created on replica A cannot be validated by replica B | `IDX21329: Unable to validate token` |

The `IDX21329` error means the JWT bearer middleware cannot validate a token because the signing key used to encrypt or sign it is no longer available. In the BFF context, this manifests as cookie decryption failure, which logs the user out.

---

## Solution Overview

Data Protection keys are persisted to **Azure Blob Storage**. All container instances share the same key ring, which means:

- Sessions survive container restarts.
- Sessions are valid across all scaled-out replicas.
- No users are silently logged out due to infrastructure events.

```text
┌─────────────────────────────────────────────────────────────────┐
│                     Azure Container Apps                         │
│                                                                   │
│  ┌──────────────┐   ┌──────────────┐   ┌──────────────┐         │
│  │  BFF Replica │   │  BFF Replica │   │  BFF Replica │         │
│  │      1       │   │      2       │   │      3       │         │
│  └──────┬───────┘   └──────┬───────┘   └──────┬───────┘         │
│         │                  │                  │                   │
│         └──────────────────┼──────────────────┘                  │
│                            │ Shared Key Ring                      │
└────────────────────────────┼────────────────────────────────────┘

              ┌──────────────────────────────┐
              │      Azure Blob Storage       │
              │  container: dp-keys           │
              │  blob:      keys.xml          │
              └──────────────────────────────┘
```

## Architecture Components

### 1. Data Protection Registration

**File:** [`1-Presentation/MotorcycleRag.WebUI.BFF/Program.cs`](../../1-Presentation/MotorcycleRag.WebUI.BFF/Program.cs)

```csharp
var dpBlobUri = builder.Configuration["DataProtection:BlobUri"];

if (!string.IsNullOrEmpty(dpBlobUri))
{
    builder.Services.AddDataProtection()
        .SetApplicationName("MotorcycleRag.WebUI.BFF")
        .PersistKeysToAzureBlobStorage(new Uri(dpBlobUri), new DefaultAzureCredential());
}
else
{
    builder.Services.AddDataProtection()
        .SetApplicationName("MotorcycleRag.WebUI.BFF");

    if (builder.Environment.IsProduction())
    {
        throw new InvalidOperationException(
            "DataProtection:BlobUri is required in production.");
    }
}
```

**Key behaviors:**

- `SetApplicationName()` scopes the key ring to this application — keys generated by other applications are not usable.
- `PersistKeysToAzureBlobStorage()` writes the XML key ring to the configured blob.
- `DefaultAzureCredential` authenticates using the container's Managed Identity — no connection strings or secrets required.
- Production startup fails fast if `DataProtection:BlobUri` is not set.

### 2. Health Check

**File:** [`1-Presentation/MotorcycleRag.WebUI.BFF/HealthChecks/DataProtectionHealthCheck.cs`](../../1-Presentation/MotorcycleRag.WebUI.BFF/HealthChecks/DataProtectionHealthCheck.cs)

Registered as `data_protection_blob` and exposed at `/health`. It:

- Reads `DataProtection:BlobUri` from configuration.
- Attempts to connect to the blob using `DefaultAzureCredential`.
- Returns `Healthy` if the blob exists or the container is accessible.
- Returns `Degraded` if the URI is not configured (ephemeral mode).
- Returns `Unhealthy` on unexpected errors.

### 3. Monitoring Service

**File:** [`1-Presentation/MotorcycleRag.WebUI.BFF/Extensions/DataProtectionMonitoringExtensions.cs`](../../1-Presentation/MotorcycleRag.WebUI.BFF/Extensions/DataProtectionMonitoringExtensions.cs)

`DataProtectionMonitoringService` emits the following Application Insights telemetry:

| Telemetry Type | Name | Description |
| --- | --- | --- |
| Metric | `DataProtection.KeyPersistence.Success` | Counter incremented on each successful write |
| Metric | `DataProtection.KeyPersistence.Failure` | Counter incremented on each failed write |
| Metric | `DataProtection.KeyPersistence.Duration` | Milliseconds taken to persist keys |
| Custom Event | `DataProtection.KeysInitialized` | Emitted on application startup when keys are loaded |
| Custom Event | `DataProtection.KeysRotated` | Emitted when the key ring is rotated |
| Custom Event | `DataProtection.KeysLoaded` | Emitted when keys are read from blob storage |

## Data Flow

### Startup

```text
1. Program.cs reads DataProtection:BlobUri from Azure App Configuration
2. AddDataProtection().PersistKeysToAzureBlobStorage() registers the provider
3. On first access, the Data Protection system reads keys.xml from the blob
4. If keys.xml does not exist, a new key is generated and written to the blob
5. DataProtectionMonitoringService.TrackKeysInitialized() is called
```

### Cookie Encryption (Login)

```text
1. User authenticates via Entra ID OIDC
2. ASP.NET Core creates a session cookie
3. Data Protection encrypts the cookie using the active key from the shared key ring
4. The encrypted cookie is sent to the browser
```

### Cookie Decryption (Subsequent Requests)

```text
1. Browser sends the encrypted session cookie
2. Data Protection reads the key ID from the cookie header
3. Data Protection locates the matching key in the shared key ring
4. Cookie is decrypted and the user session is restored
5. If the key is NOT found → IDX21329 error → user is logged out
```

## Configuration

### Required Configuration Key

| Key | Type | Required In | Description |
| --- | --- | --- | --- |
| `DataProtection:BlobUri` | `string` (URI) | Production | Full URI to the blob where `keys.xml` is stored |

### Example Value

```text
https://<storage-account>.blob.core.windows.net/<container>/keys.xml
```

### Configuration Sources (in priority order)

1. Azure App Configuration (label: `bff`)
2. Azure App Configuration (no label)
3. Environment variables
4. `appsettings.{Environment}.json`
5. `appsettings.json`

### `appsettings.json` Default

```json
{
  "DataProtection": {
    "BlobUri": ""
  }
}
```

An empty string is treated as "not configured" — the service falls back to ephemeral keys.

### Required RBAC Permissions

The container app's Managed Identity must have the **Storage Blob Data Contributor** role on either the storage account or the specific container.

```bash
az role assignment create \
  --assignee <managed-identity-object-id> \
  --role "Storage Blob Data Contributor" \
  --scope /subscriptions/<subscription-id>/resourceGroups/<rg>/providers/Microsoft.Storage/storageAccounts/<account>/blobServices/default/containers/<container>
```

## Security Model

- Keys are stored as **plaintext XML** in the blob. Access to the blob must be restricted to the Managed Identity.
- No SAS tokens or connection strings are used. All access is via Managed Identity + RBAC.
- The blob URI must use HTTPS.
- The application name `MotorcycleRag.WebUI.BFF` scopes the key ring — keys from other applications cannot be used to decrypt these cookies.
- Key rotation follows ASP.NET Core defaults: keys expire after **90 days** and a new key is generated **14 days** before expiry.

## Environment Behavior

| Environment | `DataProtection:BlobUri` Set | Behavior |
| --- | --- | --- |
| Development | No | Ephemeral keys. Warning logged. Sessions do not survive restarts. |
| Development | Yes | Persistent keys. Normal operation. |
| Production | No | Application **fails to start** with `InvalidOperationException`. |
| Production | Yes | Persistent keys. Normal operation. |
