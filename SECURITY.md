# Security Policy

## Supported versions

Security fixes are applied to the default supported development branch and released through the repository's normal GitHub Actions deployment process. Older branches are not guaranteed to receive fixes.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub private vulnerability reporting when it is enabled for this repository. If it is unavailable, contact the maintainers privately through the support channel in [SUPPORT.md](SUPPORT.md) and include a concise reproduction, impact assessment, and safe proof of concept.

Do not include production credentials, personal data, or destructive exploit steps. Maintainers will acknowledge reports, assess impact, coordinate remediation, and disclose fixes responsibly.
